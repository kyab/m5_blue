A2DP Sink Demo — Bluetooth レイヤ構造

a2dp_sink_demo.c の setup_demo() で初期化される各プロトコルの 略称・正式名称・役割を整理したリファレンス

レイヤ構造（下から上）

Bluetooth Classic スタックは OSI モデルに似た階層構造。下位層が上位層の「運搬路」を提供する。

Layer 1
Radio

物理層（ハードウェア）

— Bluetooth Radio / Baseband

2.4 GHz 帯での RF 送受信。Pico では CYW43439 等の Bluetooth コントローラ IC が担当。 このデモの C コードからは直接触らない。

Layer 2
HCI

HCI

Host Controller Interface

ホスト（Pico / BTstack）と Bluetooth コントローラ間の標準インターフェース。 コマンド送信・イベント受信（ペアリング要求、接続完了など）を担う。

hci_add_event_handler(&hci_packet_handler)
Layer 3
L2CAP

L2CAP

Logical Link Control and Adaptation Protocol

ACL リンク上に「論理チャンネル（パイプ）」を作成・管理する。 A2DP 音声、AVRCP コマンド、SDP 問い合わせはすべて L2CAP チャンネル上を流れる。

l2cap_init()
Layer 4
Profiles

SDP / A2DP / AVRCP

Service Discovery Protocol / Advanced Audio Distribution Profile / Audio/Video Remote Control Profile

アプリケーションに近いプロファイル層。SDP はサービス目録、A2DP は音声ストリーム、 AVRCP は再生操作・メタデータを担当する。

sdp_init() / a2dp_sink_init() / avrcp_*_init()
Cross-cutting
GAP

GAP

Generic Access Profile

デバイスの「見え方」を制御する横断的プロファイル。 デバイス名、Class of Device、discoverable 設定、リンクポリシー、ペアリング応答を担う。

gap_set_local_name() / gap_discoverable_control(1)

プロファイル内の役割

A2DP — Source / Sink

Advanced Audio Distribution Profile

  • Source — 音を送る側（スマホ、PC）
  • Sink — 音を受け取る側（ヘッドホン、スピーカ）← このデモ
  • コーデック: SBC（Subband Coding）のみサポート
  • bitpool 2–53: 品質／ビットレートの交渉範囲

AVRCP — Controller / Target

Audio/Video Remote Control Profile

  • Controller — リモコン側。play/pause/skip 送信、曲情報取得 ← このデモも登録
  • Target — 操作される側。volume up/down 受信 ← このデモも登録
  • Category 1: Player/Recorder（再生操作）
  • Category 2: Monitor/Amplifier（音量操作）

SDP レコード（4 枚登録）

Service Discovery Protocol Records

  • A2DP Sink — 音声受信可能（HEADPHONE 機能マスク）
  • AVRCP Controller — 再生操作を送れる
  • AVRCP Target — 音量操作を受け取れる
  • Device ID (PnP) — ベンダー/製品識別情報

GAP 設定

Generic Access Profile

  • デバイス名 — "A2DP Sink Demo"（ペアリング一覧に表示）
  • CoD 0x240400 — Audio + Rendering / Headphone
  • discoverable — Inquiry Scan 有効（新規スキャンに表示）
  • Role Switch 許可 — スマホ側が Master になれる

接続シーケンス（用語をつなぐ）

1. GAP → "A2DP Sink Demo" / CoD=Headphone / discoverable=ON 2. スマホ → Inquiry（GAP 経由でデバイス発見） 3. スマホ → SDP 問い合わせ（A2DP Sink / AVRCP / Device ID を確認） 4. HCI → ペアリング（SSP 数値確認 → hci_packet_handler） 5. L2CAP → チャンネル確立（A2DP 用 / AVRCP 用） 6. A2DP → ストリーム確立 + SBC コーデック交渉（bitpool 2–53） 7. AVRCP → 再生操作・メタデータのやり取り開始 8. L2CAP → SBC フレームが流れ始める（handle_l2cap_media_data_packet）

Class of Device — 0x240400 の内訳

フィールド ビット位置 値 意味
Service Class bit 13, 21 0x002000 | 0x000020 Rendering (21) + Audio (13)
Major Device Class bit 8–12 0x04 Audio/Video
Minor Device Class bit 2–7 0x00 Headphones（ヘッドホン）
